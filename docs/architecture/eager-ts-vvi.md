# Eager TypeScript feature locales

Image compositor controls and navbar definitions capture raw translation strings when their modules evaluate. Their locale-only SFC dictionaries belong to drive and navigation, retain all 28 effective Misskey locales, and contain exactly the 85 distinct paths these consumers use. The two deferred navbar menu labels capture raw strings at module evaluation so later runtime activation cannot change them.

VVI documents locale-only SFCs as typed message modules: import the default owner and read `Messages.$locale` for raw strings or `Messages.$l` for formatters. Each feature accessor returns its owner's `$locale`, and each consumer calls that accessor before creating its exported eager object. Volar derives the dictionary type from the Japanese locale block; there is no duplicate authored JSON, type override, custom registry, or locale loader adapter.

The existing plugin scans these owner SFCs under its packages root. It assigns `/features/drive/frontend/utility/image-compositor-functions/messages.vue` and `/features/navigation/frontend/navbar-messages.vue` as canonical module identities. The virtual strategy generates typed lazy owner proxies against these identities and includes all 28 dictionaries in its normal locale payloads. The entry loads and activates the runtime before dynamically importing main/sub boot, so eager consumer reads happen after activation. The owner import itself does not read a translation.

The inline-chunks strategy transforms owner `$locale` expressions to owner markers and substitutes selected-language dictionaries into localized chunks through the package's ordinary production chain. The owner's default import keeps the transformed owner expression in the consumer graph. A literal-host `useLocale` call is not equivalent: inline runtime payloads contain empty modules, and its TS rewrite handles only `import.meta.url`. A side-effect SFC import does not register runtime payloads. Direct default-owner `$locale` access is therefore the supported API shared by both strategies. The production strategy is unchanged.

All 136 accesses in this migration are raw strings: 111 drive eager accesses, 23 navbar eager titles and two deferred navbar menu labels. Calling a localizer for a static label can interpret message syntax and alter translation bytes. Locale blocks retain effective `i18n.locales` bytes after the existing empty-string removal and regional/English/Japanese fallback, rather than raw YAML text. No Crowdin locale YAML is edited.

The proof fixture reverses only import/setup/access rewrites to recover each original consumer byte for byte. Tests exercise generated payloads and actual consumer sources for every supported language, compare raw labels and concatenated suffixes, and check that captured eager values survive a later active-runtime change. Both build strategies are tested through supported package hooks and isolated production fixtures. Main global messages remain absent; embed scanning excludes these owner SFCs.
