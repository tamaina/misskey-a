# Fresh passkey パスワード変更の実機確認

この Draft を適用した使い捨てテスト環境で行います。本番への適用・実ユーザーの資格情報による検証は、この手順に含みません。自動検証は合成署名とブラウザー API の mock を使っており、以下の実機結果はまだ未確認です。

## 準備

- WebAuthn が使える secure context と、環境の URL/RP ID に対応する passkey を用意します。localhost または信頼された HTTPS のテスト環境を使ってください。
- テスト用アカウントで TOTP と passkey を登録し、復旧コードを手元に保存します。独立 passkey MFA の有効化は行いません。
- 一度ログインし直し、個別 browser session を使います。旧 shared token のままの場合、新しいボタンは表示されません。
- 別ブラウザーにも同じテスト用アカウントでログインしておくと、失効を確認できます。

## 成功と既存経路

1. 設定 → セキュリティを開きます。従来の「パスワードを変更」と、「パスキーでパスワードを変更」ボタンが表示されることを確認します。
2. passkey 側を選び、現在のパスワード、新しいパスワード、再入力を入力します。
3. 端末で PIN・生体認証などの user verification を完了します。確認後、新しいパスワードで別のテスト用ログインが成功し、古いパスワードでは成功しないことを確認します。
4. TOTP・passkey の登録状態と復旧コードの残数が変わらないことを確認します。
5. 従来の変更ボタンも、現在のパスワードと TOTP/復旧コードで変更できることを確認します。passkey を使わない利用者の既存経路を残しています。

## キャンセル・失敗

1. 各パスワード入力でキャンセルし、変更が送信されないことを確認します。
2. passkey の端末画面でキャンセルします。新しいパスワードは保存されず、TOTP 経路へ勝手に切り替わらないことを確認します。
3. 現在のパスワードを誤入力します。passkey の確認に進まず、変更されないことを確認します。
4. ボタンを連打しても、入力手順や passkey の確認が二重に始まらないことを確認します。
5. passkey の確認中に設定ページを離れ、戻って再表示した後で古い端末の確認を完了しても変更されないことを確認します。

## 期限と失効（開発者ツールを使える場合）

1. Network で `/api/i/change-password/passkey/start` → `/complete` の順を確認します。成功時は start が200、complete が204です。
2. `/complete` に対する fetch/XHR breakpoint を設定し、送信直前で JavaScript を止めます。start 成功から95秒以上待って再開すると、変更は拒否され、古いパスワードが有効なままになります。再試行は新しい開始から行います。
3. 同様に complete 送信前で止め、別ブラウザーからテスト用アカウントのログイントークンを再生成します。最初のブラウザーを再開すると session が拒否され、パスワードが変更されないことを確認します。
4. breakpoint を解除し、通常の新しい手順が完了することを確認します。

## 結果の記録

OS・ブラウザー/バージョン、認証器の種類、各項目の成功/失敗/未実施だけを共有してください。パスワード・token・ticket・credential・復旧コードや、これらを含む HAR/リクエスト本文は共有しません。

利用できる端末の PIN/生体認証、外付けキー、端末間 passkey を区別して記録します。実施できない組み合わせは未実施のまま残し、自動テストの成功で代用しません。
