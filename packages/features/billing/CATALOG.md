# Scheduled catalog prices

Continuation of Issue171 above refund PR174. Price periods, source duration/price ordering, 56-day reference evaluation, previous/current/next display and immutable historical price units are native service-offer procedures. Existing undated offers remain usable without inventing their history. Administrators enter UTC selling dates and add a new offer ID for each new price. Dated catalog entries also support the source zero base price through a mandatory server quote and the existing zero-payable transaction; undated legacy zero prices remain invalid. End-only input is rejected; unchanged minute-level editing retains original milliseconds.

`catalogPriceId` identifies one price across equivalent settlement deployments declared by `pricingAssetKey` and matching decimals. All its terms must match. Histories deduplicate the logical price; its expiration updates across deployments under one advisory transaction lock. Other overlaps for the same asset/plan/duration are rejected; longer duration cannot cost less than a concurrently sold shorter duration (source comparator anchored to UTC2024-01-01). Price amount, duration, start, asset/plan identity and logical price ID cannot be overwritten after recording a dated price. Quotes/order creation use the server's half-open selling interval; confirmed order snapshots and funded terms remain independent of later catalog changes.

The source deal kernel and its tests are ported without algorithm changes. Adapter difference: cfw-fileup's current adapter marks expired history inactive, preventing it from contributing to reference selling time. Native history retains the administrator's enabled selling periods, matching the source kernel's historical-reference test cases. This represents declared offering history, not measured transaction volume. Undated legacy rows never contribute. Inactive deployments cannot make a reference eligible when every corresponding row is disabled.

Native account catalog uses configured RPC availability and displays a reference strike-through only when the server's source rule permits it. It shows previous/current/next period and next start. Separate asset/deployment lifecycle and metadata RPC administration, region/tax/residency/seller settings, receipt email/PDF and admin sales summaries remain later Issue171 procedures; this document does not claim the entire migration complete.
